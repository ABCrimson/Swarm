# ADR-0011: The PR body: code-generated evidence first, model prose second

- **Status:** Accepted
- **Date:** 2026-08-15

## Context

A ship should leave a PR body that cites what the worker actually did. Evidence must be generated by
code from the event log. Prose may be generated by a model. The two must never be confused, because a
model can invent a citation, a table, or a heading that looks authoritative.

## Decision

**Turns come from the `agent_*` family, not `agent_turn_started`.** The first plan assumed a turn's
root event was `agent_turn_started`. The code has two AI paths with different correlation-id spaces:
the webview chat calls `agent_turn_started` once per turn only to obtain a `causeSeq`, with a chat-item
`requestId` that is not a `TurnId`; the Claude Code adapter generates its own `TurnId` and never emits
`agent_turn_started`. A record keyed off that event would show zero turns for every adapter-driven
worker, which is fabricated emptiness. `git::causal::build_ship_context` instead groups
`agent_block`, `agent_tool_call`, `agent_tool_result` and `agent_turn_settled` by their own `turnId`.
`agent_turn_started` rows are used only to set `has_uncaptured_webview_activity`, so an empty record
says either "no recorded agent turns" or "this worker's activity is not captured (webview chat path)",
never one sentence for both.

**Scoped in SQL.** `ship_context` reads through `EventLog::events_for_worker_between`, which filters by
worker and event type in SQL and fetches newest first, trimming the old end. An earlier range-wide row
cap applied before the per-worker filter could silently drop the shipping worker's newest turns while
reporting zero omitted. Truncation from either source renders the same single sentence.

**An allowlist is the no-secrets boundary.** `extract_target` reads only `path`, `file_path`,
`filePath`, `command`, `cmd`, `pattern`, `url`, `query` and `name` from a tool call's input, capped at
200 characters, never `content`, `body`, `text` or `data`. The prompt for the prose is assembled in one
place from the diff-stat numbers, the branch names, and each turn's status and tool `name`, `target`
and `ok`; a source-scan test asserts the module never imports the config reader.

**Order and honesty.** `composeShipBody` renders the deterministic Causal Record first and the model
prose after it, separated by a rule, so the first `## Causal Record` heading in the body is always the
code-generated one even if the model writes its own. `stripUnknownSeqCitations` removes any `[seq N]`
whose `N` is outside the commit's `(seqFrom, seqTo]` range, unconditionally. No key, a network failure,
a refusal or never clicking Generate renders the deterministic section alone, and shipping never
blocks on the prose.

## Consequences

- The tool-driven side effects of the webview chat (spawns, input) are not in the record; they are
  differently shaped and merging them would blur the evidence boundary. A separate labelled section
  could add them later.
- The window between a commit landing and its `commit_created` event becoming queryable is uncited.
- `ship_context` is `RemotePolicy::Allowed`: it is read-only and exposes only what preflight already
  does about the same worker.
