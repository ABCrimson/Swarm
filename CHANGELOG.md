## [Unreleased]

The `modernize/2026-09-23` branch: a Tauri 3 desktop shell, a rewritten agent and event core, hardened git and `swarmd`, a rebuilt frontend, and the newest release of every dependency on every channel. Rust gates run on `nightly-2026-10-14` (rustc 1.101).

### Breaking

- **Tauri 3.0 (alpha) replaces Tauri v2.** The whole stack moves together: `tauri` and `tauri-runtime-wry` `3.0.0-alpha.4`, `tauri-build` `3.0.0-alpha.3`, the fs/opener/store/updater/notification plugins `3.0.0-alpha.2`, `tauri-plugin-dialog` `3.0.0-alpha.3`, and the matching `@tauri-apps/*` JS packages. The webview runtime is chosen explicitly (`Builder::default().runtime(Wry::default())`). Anything built against the Tauri v2 API, capability files or `tauri.conf.json` shape must be ported. `tauri-plugin-shell` is gone, replaced by `tauri-plugin-opener`.
- **fs permission rename.** `tauri-plugin-fs` 3.0.0-alpha.2 removed the `read_text_file` and `write_text_file` commands. The capability identifiers `fs:allow-read-text-file` and `fs:allow-write-text-file` are now `fs:allow-read-file` and `fs:allow-write-file` (`readTextFile`/`writeTextFile` call `read_file`/`write_file`), and `fs:allow-stat` is granted for the workspace size pre-check. Custom capability files and any code naming the old identifiers need the rename.
- **Per-command ACL for the app commands.** `src-tauri/build.rs` generates `allow-<command>`/`deny-<command>` for each of the 38 app commands (`AppManifest::commands`, fed by `src-tauri/src/commands/command_list.rs`, the list the `commands!` macro forwards). `capabilities/default.json` grants each one, and an ungranted command is callable by no webview. Custom capability files must list the `allow-*` entries they need.
- **Dialog-grant-only filesystem access.** The webview no longer holds a static fs scope on `$HOME/**` or `$APPDATA/**`. Only paths the user picked in an open or save dialog are reachable, with a deny scope over the app data directory (API key, event log, daemon token) and common credential stores. Browsing a workspace's subdirectories needs the folder picker's `recursive: true`, and exports to a dialog-picked path are written in place. The unused `fs:allow-mkdir`, remove and rename grants are dropped.
- **Command arguments are normalized before `RemotePolicy`.** Remote clients can no longer slip denied arguments past the policy through alternate spellings, and `is_secret_key` is tighter. Clients that relied on the old behavior will be refused.
- **Desktop shell rewrite.** The hand-written command wrappers are replaced by registry forwarders generated by one macro. Command names, argument keys and success values are unchanged; errors are now the registry's own JSON, identical to what `swarmd` returns.
- **Toolchain floor** (see the table below): a Rust nightly at 1.101 and a Node 27 nightly are required.

### Fixed

- **Events fail closed.** An event whose seq cannot be reserved or whose append to the log fails is no longer emitted anywhere: not to the webview, not to the broadcast fanout, and `head_seq` does not move. The caller waiting on that event's seq is told. A failed append leaves a one-seq gap that an ephemeral `system_log` error explains, and clients skip it on backfill; a failed reservation rolls the seq counter back, so it leaves no gap, and events are dropped until the log recovers. Before, a failed append was logged and the event was delivered anyway, so a client could hold events the log could not replay. `worker_state` is emitted under the registry entry lock, and `reap()` trusts `try_wait()` over a kill's return value (portable-pty 0.9.0's `kill()` result is only advisory).
- **Persistence and events.** The config and sessions files are never clobbered when damaged, and writes are durable and atomic; `plugin-store` no longer overwrites Rust-owned config; deleting a session deletes its snapshots; a late permission answer never overwrites an expired request; custom tools keep legacy free-text parameter names; templates re-read after a write.
- **Git.** The ship chain and git runner use a deny list, porcelain v2 `-z`, raw stdout, graceful timeouts and stdin pathspecs; a timed-out git leaves no `index.lock`; an orphaned prose stream aborts on unmount.
- **Desktop shell.** The "already running" dialog no longer deadlocks on the main thread (certain on macOS); the single-instance lock is released on drop; the release log is written from a background thread and flushed at exit; "Open Compare Page" works again (the old shell `open` regex rejected every https URL) and compare pages work on any GitHub host; dialog-granted folders reach their dot entries on macOS and Linux; `ClientFrame`'s `Debug` never prints the daemon token or RPC args; IPC spans stop recording prompts, file contents and keystrokes.
- **Workers and agents.** No console window for provider CLIs on Windows; no fragments after a line overrun; capacity reserved before side effects; the PTY master is kept; `session_remove_worker` keeps its provenance; workers rehydrate on startup and the detail panel does not leak state across workers.
- **Tools and AI.** Every tool input is validated, custom-tool schemas are safe, the `run_command` copy is honest; executed tool results are recorded on cancel and a refusal rolls back only its round; system injections are never stranded.
- **UI.** Error-boundary retry budget and honest labels; SplitPane persists once per drag and clamps stored sizes; lossless JSON/JSONC highlighting; log tail-follow that follows, with deferred search; palette spawn/kill really act, with unique names and a 10 s kill confirmation; one distinguishable colour per metric; opaque terminal selection color; reduced motion also zeroes delays; per-type toast colors; xyflow base styles restored; the history date range ignores a bound `Temporal` cannot read; the app renders at once outside the desktop shell; `swarmd`'s served UI loads runtime `<style>` elements and `data:` fonts, and a missing `/assets` file is never marked immutable; the workspace file tree renders every visible row (it drew only the overscan rows before) and the file viewer refuses files over 2 MiB and binary files; palette ranking uses modern-cmdk's persisted frecency.
- **Remote UI transport.** The `swarmd` WebSocket transport subscribes before the first connect, rejects structured RPC errors unchanged (as Tauri IPC does), bounds the handshake, ignores stale sockets' handlers, ignores a malformed `#t=` fragment instead of blanking the app, stops reconnecting on a refused token (4401), and replaces half-open sockets.
- **Session export.** The round-trip, template capture and citation stripping.
- **Browser build and startup state.** Desktop-only controls gate on `hasCapability()` and show "Available In The Desktop App Only" instead of failing, `checkForUpdates()` rejects with "Update Checks Need The Desktop App" rather than reporting up to date, and the Settings API key form and the Ship preview's summary generation are disabled without the webview AI chat (the key is never read over `swarmd`), and session delete confirms with `window.confirm` without the Tauri bridge. Startup session restore replays deletion and worker-membership events received while the snapshot loads. The agent concurrency cap ("AI Concurrent Stream Limit") is acknowledged by the backend: it rolls back with an alert and Retry on failure or a 10 s timeout, and adopts the backend's value at launch. The spawn dialog's header close button respects the mid-spawn guard.
- **Ship over `swarmd`.** A ship commit or push no longer fails at 30 s: each ship command waits for the sum of the daemon's git budgets it can run plus a margin (`rpcDeadlineMs`, pinned to `git/cli.rs` by a test). A lost reply, a reply past its deadline, or a late `ship_settled` receipt shows as "Awaiting Confirmation" with no retry button and reconciles from the replayed ship events, then returns to idle for a preflight reload if nothing arrives. A link watchdog closes a socket that goes silent under a pending call. The browser build no longer calls the desktop opener after a ship.
- **Killing a worker stops its agent first.** `kill_worker` used to remove the worker, its shell and its worktree before it shut the agent session down, so a provider turn could keep running against a checkout being deleted, and a session still in its handshake could outlive the kill. The kill now marks the worker closing, waits for attaches in flight, shuts the session down (and waits for any other shutdown of it already running, from a second kill or `agent_shutdown`), and only then kills the shell and reconciles the worktree. While a worker is closing, `agent_spawn`'s attach, `agent_send_turn`, `agent_cancel` and `agent_permission_respond` fail with the new error ``Worker `<id>` is closing``. When `kill_worker` returns, no session of the worker is registered, handshaking or shutting down ([ADR-0040](docs/adr/0040-kill-stops-the-session-first.md)).
- **The ship receipt, the concurrency cap and the stop budget now match what the server did.** `ship_compare_url` settles its receipt from the worker's own recorded push (`PushRecord`), so it no longer takes `commitSha` or `pushedRef` and the receipt cannot carry a value the caller made up. `set_agent_concurrency` and `set_max_workers` reply with the cap in force, and the app shows and acknowledges that value and keeps one call of each in flight (a value requested meanwhile waits in a one-slot queue and goes out when the call settles or its 10 s ack timeout fires, and a call that settles late after a newer one makes the app send the latest value again), because the daemon orders calls only from the moment each reaches its lock. `swarmd` gives workers 40 s to stop (`STOP_WORKERS_TIMEOUT`, was 10 s, shorter than an adapter's 30 s handshake plus teardown), and `TimeoutStopSec` (`swarmd.service`) and `ExitTimeOut` (`dev.crimson.swarmd.plist`) are 60 s; the Windows Scheduled Task still stops without a graceful window. Snapshots, saved templates and automatic snapshots gate on a new `localStores` transport capability instead of `isTauri()`, so the browser build served by `swarmd` disables them.
- **The event log survives power loss.** It now commits with `synchronous=EXTRA` (FULL's per-commit WAL sync in WAL mode) and `fullfsync=1` (so macOS flushes the drive cache) instead of `synchronous=NORMAL`, and refuses to open with anything weaker, so a committed event and a seq reservation now survive an OS crash or power loss as well as a process crash (on storage that honours flushes), and a seq is never reissued after one. Each persistent event now waits for a flush of the `-wal` file, and events queued behind it wait too: measured on ext4 in a WSL2 VHD, about 2 ms per event (roughly 500 events/s against about 27,000 with `NORMAL`); through `/mnt/c` about 1 ms more at p50 ([ADR-0039](docs/adr/0039-event-log-flushes-every-commit.md), [Performance](docs/performance.md)).
- **Overlapping settings changes no longer leave the file and the live cap disagreeing.** Two concurrent `set_agent_concurrency` or `set_max_workers` calls could leave the file holding one value and the live cap another. Each command now holds its setting's lock (FIFO) across the config write and the live apply. Calls apply in the order they reach the setting's lock, and the file and the live cap always end on the same value. Each request runs as its own task, so two requests sent without waiting for the first reply can reach the lock in either order; the app therefore keeps one `set_max_workers` call in flight, as it does for `set_agent_concurrency`: a Worker Registry Cap committed meanwhile waits in a one-slot queue (the latest value replaces any older one) and goes out when the call settles or its 10 s ack timeout fires, and a failure rolls the field back with an alert and Retry. Each reply is the cap in force once that call has applied (a number; it was `null`).
- **Ship size guard measures the committed blob.** A staged-only commit is the index, but the 5 MiB deny rule read the working-tree file, so a blob staged over the limit and then shrunk on disk was committed. Staged mode now measures the index blob (`git ls-files --stage`, then `git cat-file --batch-check`); "all" mode measures the file about to be staged, and the index is measured again right before `git commit` in both modes. The guard holds before hooks run: a pre-commit hook runs inside `git commit` and can stage a file it never measured. Non-UTF-8 file names are matched the way the status snapshot decodes them.
- **Push binds the commit, not the branch.** `git_push` resolved a sha and then pushed `refs/heads/<branch>`, so a commit that landed in between was pushed while the receipt named the older sha. It now pushes `<sha>:refs/heads/<branch>` (still never forced), resolves the sha from the branch tip it already read, and records the upstream afterwards (a sha source does not set one). Every successful push is also recorded in the worker registry, and the compare page and its receipt read that record, not the caller or the live branch. `PushOutcome` gains `remote` and `remoteRef`.

### Security

- **One escaping module for displayed paths and names.** `escapeForDisplay` moved out of `ApprovalArgs.tsx` into `src/lib/display-escape.ts`, and the file viewer now escapes its header, its tooltip and the contents region's accessible name too (a path containing a right-to-left override, U+202E, shows the visible text `\u202E` instead of silently reordering). The agent chat, approval rows and ship preview import the same function.
- **Agent sessions trust no repo configuration** ([ADR-0038](docs/adr/0038-agent-provider-trust-model.md)). A repo's `.claude/settings.json` could run commands (`apiKeyHelper`) and redirect the CLI (`env`) before any approval; the Claude Code probe and every tier now pass `--setting-sources ""`, and SWARM appends only the repo's `permissions.deny` strings (at most 8 KiB of JSON) to the inline deny list. As a result a Standard or WriteEnabled worker no longer receives the repo's `CLAUDE.md`, `.claude/rules`, `.claude/skills` or `.claude/agents`. The probe runs in a fresh private directory instead of the shared temp root; every tier denies `EnterWorktree` and `ExitWorktree` and Restricted also denies `PowerShell`, `DesignSync`, `WebSearch` and `PushNotification`; bypass and auto permission modes are disabled in the inline settings. Both adapters refuse a relative, empty or missing working directory and find the CLI only on absolute `PATH` entries (an npm `claude.cmd` maps to its `claude.exe`).
- **Webview AI tools ask first.** `run_command`, `spawn_worker`, `kill_worker`, `write_file` and `read_file` wait for the user's approval (Allow Once, Allow For Session or Deny) inside their own `execute`, so no caller can skip the gate. A session grant covers one exact call, keyed by tool, worker and argument (the exact command string, the path as given, the worker name for `spawn_worker`); it never releases another pending call, and `write_file` never gets one. The prompt lists every validated field that will run as escaped data (backslashes doubled; newline, carriage return and tab as `\n`, `\r`, `\t`; other control, bidi and zero-width characters as `\uXXXX`), and a long value is cut with a count of the hidden characters: Allow stays disabled until each cut value has been expanded once, and commands and file paths are never cut. Stopping a turn or killing its worker denies the turn's pending tool calls, so neither leaves a parked turn or its stream slot behind.
- **`read_file` and `write_file` scope.** The paths are canonicalized (symlinks resolved, an existing write target included, which also expands Windows 8.3 short names) before the scope and deny-list checks, and the deny list compares names case-insensitively: `swarm-config.json` (the API key), the daemon token and its `.daemon-token.<rand>` mint-time temp file, the backup files named after them, and `~/.ssh`, `~/.gnupg` and `~/.aws`. On Windows a write is refused when the file name contains `:` (an NTFS alternate data stream), ends in `.` or a space, or is a device name (`CON`, `NUL`, `COM1`, `COM¹`, ...).
- Dialog-grant-only filesystem scopes with a deny scope over secrets (see Breaking); devtools excluded from release builds; command args normalized before `RemotePolicy`; `is_secret_key` hardened; daemon token and RPC args redacted from `Debug`; `swarmd` admission and auth hardened; browserslist refreshed for GHSA-73wf-gq98-2v4g; least-privilege, SHA-pinned workflows with attested releases; per-command ACL for the app commands (see Breaking).
- **`worker_input` previews no longer leak credentials the terminal would reassemble.** The preview stripped control characters one at a time before redacting, so a credential edited with backspace or DEL, split by an escape sequence, a readline editing key, or an invisible code point reached the event log and the `swarmd` fanout unredacted. The preview is now withheld (`[preview withheld: line editing]`) when the input contains any control other than CR or LF (BS, DEL, TAB, ESC, C1 controls). Otherwise the raw text is redacted, every format and default-ignorable code point is dropped, CR and LF become spaces, and the text is redacted again before the 120-character cut. CR overwrite is not modelled: readline ends the line at CR, so the shell receives two lines.
- **WebView2 SmartScreen stays on.** `additionalBrowserArgs` replaces wry's Windows default, and the string had copied that default verbatim, including `msSmartScreenProtection`. SmartScreen vets downloads and navigations, so the flag is dropped (`msWebOOUI`, `msPdfOOUI` and WebGPU stay) and the policy is pinned in `config_contract`.
- **The release verifier sends its token only to this repository's asset URLs.** `verify-updater-manifest.sh` sent the job's `contents: write` token to every `platforms.*.url` in `latest.json`. Each URL is now checked up front against two forms scoped to `$GITHUB_REPOSITORY` (`api.github.com` asset URLs and `github.com` release downloads); only the API form carries the token, and curl is pinned to https and never follows a redirect with the token (`--location-trusted` is not used).

### Fixed — Phase 2 review wave (adapter contract + NDJSON framer hardening)

- **NDJSON framer O(n²) scan amplification.** The framer's `\n` search re-scanned the retained partial-line prefix from byte 0 on every `push()` call — for a large line fed in `spawn_piped`'s 4096-byte read chunks, this measured ~13.4B byte-comparisons for a single 10MB line (a >1000x blowup). Fixed with a persistent `scan_from` cursor: each byte is now scanned at most once over the framer's lifetime. A test with an instrumented scan-byte counter proves linear behavior and fails against the pre-fix code.
- **No line-length cap.** An unterminated line (a desynced/non-NDJSON provider) grew the framer's buffer without bound. Added `MAX_LINE_BYTES` (10MB); an overrun returns a typed `AppError::LineTooLong` that `spawn_piped` surfaces via a new `PipedHandle::framer_errors` channel — the framer clears its own buffer and keeps parsing subsequent lines, but the caller must treat the overrun as a session-level failure (never silently truncate JSON).
- **`AgentSession::shutdown` contract change** (binding before any Phase 3 adapter is built against it): `shutdown(self: Box<Self>)` → `shutdown(&self)`, now idempotent (a second call returns the cached `ExitSummary`, never re-kills or re-emits) — this is what lets a session live behind `Arc<dyn AgentSession>` instead of a one-shot `Box`. The trait's doc now states the full concurrency contract as binding: `send_turn` while a turn is in flight returns a typed `AppError::AgentSessionBusy` (a session never queues — that's the scheduler's job); `cancel` may race `send_turn`/`shutdown` safely; no internal lock may be held across an `.await`; and Condition B is restated as a hard invariant — shutdown (or child death) during an in-flight turn yields EXACTLY ONE synthesized `agent_turn_settled`, never zero, never two. `MockAgentSession` gained interior mutability and an ownership handshake between `send_turn`/`shutdown` to prove it; new tests cover shutdown-during-in-flight (exactly one settled), double-shutdown (idempotent), and send-while-busy.
- **`agent_turn_settled.status` is now a closed `AgentTurnStatus` enum** (`Ok`/`Error`), matching the `ProviderId`/`PermissionDecision` precedent this branch already set, rather than a bare string.
- **Piped-process substrate hardening:** `PipedHandle::kill_and_wait` mirrors the PTY reap pattern (drop stdin, kill, wait) so nothing forgets to reap a child; stderr now retains a live, bounded ~4KB tail (`PipedHandle::stderr_tail`) instead of only a byte count, so a provider's fatal startup message is recoverable; `spawn_piped` documents the runtime it requires (`# Panics` if called outside a Tokio context).
- **Credential-leak regression coverage extended to the command layer:** a second span-capture test (`commands::worker::tests`) reproduces `spawn_worker`'s own `#[tracing::instrument]` shape (no live `tauri::App` harness exists in this codebase, so it mirrors the established `WorkerInputArgs` shadow-struct pattern) and asserts no env secret leaks there either.

### Phase 1: ordered event core

Replaces the legacy per-channel event system with a single ordered channel. Every backend event -- worker, session, AI streaming, metrics, logs, bus messages -- now flows through one `swarm://events` Tauri channel as a `{ seq, ts, type, payload }` envelope, assigned by a single-writer `OrchestrationEngine` running on its own thread, so wire order is total across every event type.

- **Single-writer engine:** `OrchestrationEngine` (`src-tauri/src/orchestration/engine.rs`) owns one dedicated writer thread that every `emit_event()` call is routed through; it assigns the monotonic `seq`, persists per policy, and emits -- eliminating the possibility of two threads racing to claim the same sequence number
- **SQLite append-only log:** events are persisted to `<app-data>/swarm-events.db` (WAL mode, `events(seq PRIMARY KEY, ts, type, payload) STRICT`); sequence numbering resumes from the log's max `seq` across restarts
- **Persistence policy:** `worker_output`, `system_metrics`, and `system_log` are high-frequency telemetry -- they consume a `seq` and flow live but are never written to the log. Every other type (`worker_spawned`, `worker_killed`, `worker_state`, `session_created`, `session_deleted`, `ai_stream_delta`, `ai_stream_settled`, `bus_message`) persists
- **`ai_stream_settled` receipt:** a new terminal event emitted exactly once per AI request, after the final `ai_stream_delta`, on both success (`status: "ok"`) and failure (`status: "error"`, with `error` set) -- the receipt pattern that replaces inferring completion from a stream event's `done` flag. (Frontend consumption is not yet wired to a UI -- this lands the contract.)
- **`events_since(after_seq)`:** a new IPC command returning persisted envelopes ascending, capped at 5000 rows per call, for gap backfill and replay
- **Frontend event bus:** `src/lib/event-bus.ts` replaces all `listen()`-per-channel call sites with `connectEventBus()` + `onEvent()`/`waitFor()`; envelopes are zod-validated, sequence gaps trigger an `events_since` backfill with a pending-buffer to preserve ordering against concurrently-arriving live events
- **Legacy per-channel events removed:** `worker:spawned`, `worker:killed`, `worker:output`, `worker:state`, `session:created`, `session:deleted`, `system:metrics`, `ai:stream_delta`, `system:log`, and `swarm://bus-message` are no longer emitted as distinct Tauri channels -- `emit_event()` now routes exclusively through the engine

### BREAKING CHANGE

Any code still calling `listen("worker:spawned", ...)` (or any other legacy per-channel name) against the Tauri backend will no longer receive events. Subscribe via `swarm://events` and the `type` field, or use `src/lib/event-bus.ts`'s `onEvent()`.
